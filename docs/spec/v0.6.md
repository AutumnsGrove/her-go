## Proactive Mood Check-ins

Mira texts YOU on a configurable schedule (every few hours, or at specific times). Uses Telegram inline keyboards for frictionless responses — no typing required.

```
┌─────────────────────────────────────┐
│  Hey, how are you feeling right now? │
│                                     │
│  [😊 Great] [🙂 Good] [😐 Meh]     │
│  [😔 Rough] [😞 Bad]               │
└─────────────────────────────────────┘
```

Follow-up is contextual: if you tap "Rough", Mira asks a brief open-ended follow-up ("What's going on?"). If "Great", she might just acknowledge warmly and move on. The mood data feeds into her memory — she can notice patterns over time ("you've been feeling rough most afternoons this week").

**Telegram inline keyboards** (telebot `ReplyMarkup` with `InlineButton`) can also be used for:
- Quick yes/no confirmations ("Want me to create a task for that?")
- Rating things she recommends ("Was that book suggestion helpful?")
- Multi-choice questions during reflection prompts

## Weather & Location Awareness ✅

Lightweight environmental context. Mira knows what the weather is like where you are, so she can reference it naturally ("stay dry today" / "nice day to work outside").

**Implemented.** `weather/weather.go` fetches current conditions from Open-Meteo and `tools/get_weather` exposes them to the agent (optionally for a one-off location). `set_location` resolves a place through `integrate.Geocode` and stores lat/lon + timezone in config. `WeatherConfig` in `config/config.go`.

Note: there is no passive weather prompt layer — the `chat_weather.go` layer this section used to describe was never written, so weather reaches Mira only when the tool is called. Forecasts are [#27](https://github.com/AutumnsGrove/her-go/issues/27).

- Weather data via a free API (OpenWeatherMap or Open-Meteo — no API key needed for Open-Meteo)
- Location configured in `config.yaml` (lat/lon or city name) — not GPS tracking
- Fetched on a schedule (hourly or on first message of the day), cached locally
- Injected into the system prompt as environmental context
- Mira doesn't announce the weather unprompted — she weaves it in when relevant

## Mood Tracking (Internal) ✅ — redesigned

**Implemented, then redesigned.** See [`plans/PLAN-mood-tracking-redesign.md`](../plans/PLAN-mood-tracking-redesign.md). The original 1–5 `rating` schema described below is gone.

Current shape: the `mood/` package runs a post-turn **mood agent** that infers valence, labels and confidence from recent conversation, with confidence-based dedup and supersede columns (`superseded_by`, `supersede_reason`) so entries are corrected rather than duplicated. Vocabulary lives in `mood/vocab.yaml` (Apple State-of-Mind-style valence buckets, labels, associations) and daily rollups are a scheduler extension (`mood/task.yaml`).

Actual `mood_entries` columns: `ts`, `kind`, `valence`, `labels` (JSON), `associations` (JSON), `note`, `source`, `confidence`, `conversation_id`, `embedding`, `superseded_by`, `supersede_reason`.

The old schema, for historical reference:

```sql
CREATE TABLE mood_entries (      -- superseded, do not use
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    timestamp DATETIME DEFAULT CURRENT_TIMESTAMP,
    rating INTEGER NOT NULL,     -- 1-5 scale
    note TEXT,
    tags TEXT,                   -- JSON
    source TEXT DEFAULT 'checkin',
    conversation_id TEXT
);
```

**Apple HealthKit bridge (#31):** closed as not-pursued. The `her-health/` Swift CLI was never started and there is no HealthKit code in the tree.

## Morning Briefing — superseded by scheduled worker briefings

The original plan (a `scheduler.morning_briefing: true` flag driving a fixed `run_prompt` task) was never implemented — no such config key exists. What shipped instead is general: the agent can create **recurring worker briefings** from conversation via `create_schedule` with `task_type: worker_briefing` and a `topics` / `depth` / `detail` payload. Multiple briefings can coexist with different crons.

See [`plans/HANDOFF-scheduled-briefings.md`](../plans/HANDOFF-scheduled-briefings.md) — shipped.

## Medication Check-In

A gentle evening ping: "hey, how are you feeling today?" — with awareness of medication schedule as context.

- Knows med schedule as facts (stored via normal conversation, not a special schema)
- Logs mood/side-effects as structured data over time
- Timeline you can show your psychiatrist: mood + medication correlation view
- Uses the same inline keyboard pattern as mood check-ins for quick responses
- Future: HealthKit sync for medication reminders on phone

## Proactive Follow-Ups

Scan recent high-importance facts for things worth following up on. Runs as a conditional `run_prompt` scheduled task (see [Scheduler spec](scheduler.md)).

- Job interview tomorrow → "good luck today" morning message
- Mentioned feeling rough → check in next day
- Started a new medication → ask how it's going after a few days
- **Damping matters** — not annoying, just attentive. Max 1-2 proactive messages per day outside of scheduled check-ins.
- Implementation: a periodic job scans facts with `importance >= 7` and `timestamp` within the last 48 hours, feeds them to the LLM with a "should I follow up on any of these?" prompt

## Location-Aware Context ✅

**Implemented.** `tele.OnLocation` and `tele.OnVenue` handlers in `bot/tg_handlers_location.go`. Locations stored in a dedicated `location_history` table (not facts) with source tracking ('pin', 'venue', 'text', 'search'). Location shares run through the full agent pipeline so Mira can respond naturally.

- User shares location via Telegram → stored in `location_history`
- Telegram pin drops and venue shares both handled
- **Not GPS tracking** — only when you explicitly share. Mira never asks for location.
- Location history preserved for future analysis (routine detection, visit frequency)

## Nearby Search (Places API) ✅

**Implemented.** Foursquare Places API v3 (`integrate/foursquare.go`) with Nominatim geocoding (`integrate/geocode.go`). Deferred `nearby_search` tool in the `places` category. Falls back to Tavily web search when Foursquare isn't configured.

- Flexible location input: place names, addresses, coordinates, or "use my last known location"
- Three-tier location fallback: explicit location → `location_history` → weather config (home base)
- Foursquare free tier: 10,000 calls/month, returns name, address, distance, categories, open/closed estimate
- Nominatim (OSM) geocoder handles addresses and POIs — free, no API key
- All location interactions automatically recorded in `location_history`
- **Privacy:** only coordinates + search query leave the device

**Result:** Mira is aware of your tasks, your weather, your medication, and your wellbeing. She reaches out instead of waiting. She follows up on things that matter. She has buttons. She knows where you are (when you tell her) and can find things nearby.
